# ADR-0012: API Gateway y WAF en el borde con Vercel

## Estado
Aceptado. **Evidencia:** captura de las reglas del Firewall (Vercel → Firewall → Rules), del `401` devuelto por el backend a través de `/api/...` y del `403` en `/api/auditoria`.

## Criterios de evaluación
- Tener un punto de entrada único y una capa de filtrado antes del backend (DRV-005 seguridad).
- Costo cero (restricción del proyecto).
- Poco que operar: sin servidores propios ni configuración compleja.
- Poder explicar y modificar cada pieza en la sustentación.

## Candidatos
- **Reescrituras (*rewrites*) y Firewall de Vercel** delante del backend en Render.
- Kong o NGINX autoalojados.
- AWS API Gateway + AWS WAF.
- Cloudflare como proxy y WAF.

## Análisis
| Candidato | Cumple | Razón |
|---|---|---|
| **Vercel rewrites + Vercel Firewall** | Sí | Ya aloja el frontend; sin costo ni servidor nuevo; el navegador solo conoce un origen. |
| Kong / NGINX autoalojado | Parcial | Gateway completo, pero exige un servidor propio (Render gratuito no admite un segundo servicio sin costo ni sin dormirse). |
| AWS API Gateway + WAF | Parcial | Funcionalidad completa, pero requiere tarjeta y tiene costo por uso. |
| Cloudflare | Parcial | Buena opción gratuita, pero exige mover el DNS de un dominio propio que el proyecto no tiene. |

## Recomendación
**API Gateway (ligero, en el borde):**
- `vercel.json` reenvía `/api/:path*` hacia el backend en Render; el resto de rutas sirve la PWA.
- El navegador llama siempre a su mismo origen (`https://uco-kudos.vercel.app/api/...`): un solo punto de entrada, TLS terminado en el borde y sin problemas de CORS en la ruta principal.
- La variable `VITE_API_URL` del frontend vale `/api`.

**WAF (Vercel Firewall, plan Hobby, máximo 3 reglas personalizadas):**
1. **Límite de intentos de login:** `POST` a `/api/auth/login`, máximo 10 solicitudes por 60 s por IP; el exceso recibe `429`. Frena la fuerza bruta de claves.
2. **Bloqueo de rutas sensibles:** todo `/api/auditoria` se deniega en el borde (la consulta de auditoría es solo para ADMIN y el frontend no la usa).
3. Las **mitigaciones de DDoS** de Vercel están activas por defecto.

**Defensa en profundidad:** el gateway y el WAF no reemplazan la seguridad del backend. El JWT, los roles (`ADMIN` para auditoría), la validación de entradas y los límites de adjuntos se siguen verificando en el backend.

## Limitaciones (declaradas)
- **No es un producto de gateway completo** (Kong, AWS API Gateway): no valida el JWT, no transforma peticiones, no maneja cuotas por cliente ni claves de API.
- **El backend en Render sigue siendo accesible directamente** por su URL pública. El gateway protege el camino normal, pero no cierra el acceso directo.
- **Reglas administradas OWASP y Bot Protection** son de pago (planes Pro/Enterprise) y no se activan.
- El límite de frecuencia es por IP y solo cubre el tráfico que pasa por Vercel.

## Mejoras futuras
- Que el gateway añada un **secreto compartido** en una cabecera y que el backend rechace lo que no lo traiga, para cerrar el acceso directo a Render.
- Regla de bloqueo de métodos no usados (`PUT`, `DELETE`, `PATCH`) y reglas por país si el plan lo permite.
- Pasar a un gateway completo (Kong o AWS) si el proyecto sale del plan gratuito.

## Consecuencias
- Un solo origen para el navegador; CORS queda como segunda barrera.
- El comportamiento del WAF cambia sin redesplegar (las reglas se publican desde el panel), pero deben documentarse en el repositorio con este ADR.
- Los intentos bloqueados quedan visibles en Vercel → Firewall → Traffic y Audit Log (evidencia).
